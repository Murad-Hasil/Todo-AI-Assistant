# Implementation Plan: Phase 5.5 — Intelligent Scheduling with Dapr Jobs API

**Branch**: `013-dapr-jobs-scheduling` | **Date**: 2026-04-02
**Spec**: [spec.md](./spec.md) | **Research**: [research.md](./research.md)

## Summary

Extend the Todo AI backend with a Dapr Jobs-based reminder scheduler. Users ask the
AI Agent (in natural language) to schedule future reminders; the agent calls a new MCP
tool `schedule_reminder`, which POSTs to Dapr's alpha1 Jobs API via a new backend
utility. When the job fires, Dapr calls `/job/{job-name}` on the backend; the callback
handler looks up the task, then publishes to the existing `reminders` Kafka topic —
triggering the Phase 5.3 Notification Service with zero changes to that service.
The statestore.yaml is updated with a 30-second connection timeout and `keyPrefix: name`
so the Dapr Scheduler can persist jobs across cluster restarts.

**Testing**: Manual E2E via `kubectl logs` + `kubectl exec` curl; unit-testable
scheduler utility  
**Target Platform**: Minikube (local K8s), Dapr 1.13–1.17  
**Performance Goals**: Reminder scheduling confirmation < 3 s (SC-001); job fires
within ≤ 5 s of `dueTime` (Dapr Scheduler SLA)  
**Constraints**: Dapr Jobs API is `v1.0-alpha1` — not yet stable; Neon cold-start
adds up to 3 s on first connection; `reminders` Kafka topic must pre-exist in
Redpanda Cloud  
**Scale/Scope**: Single-user reminder scheduling; one-shot jobs only (no cron)

## Phase 0: Research (Complete)

All unknowns resolved. See [research.md](./research.md) for full decisions.

Key findings:
- Dapr Jobs callback path is `/job/{job-name}` (hardcoded by Dapr runtime)
- `httpx` already available — no new HTTP client needed
- `dateparser` is the correct NL-to-UTC library (configure `TO_TIMEZONE: UTC`, `PREFER_DATES_FROM: future`)
- `keyPrefix: name` is required by Dapr Scheduler for cross-restart job lookup
- Task title must be fetched from DB in callback handler (Dapr payload only carries `task_id`)
- `publish_reminder_event()` in `app/logic/events.py` is reused unchanged

### 1.2 New File: `app/logic/scheduler.py`

**Responsibility**: Pure utility — no FastAPI dependency, no global state.

**Public interface**:

```python
def parse_reminder_time(time_string: str) -> datetime:
    """
    Parse a natural language time string into a UTC-aware datetime.
    Raises ValueError if unparseable or if result is in the past.
    """

def schedule_job(job_name: str, due_time: datetime, data: dict) -> None:
    """
    Register a one-shot Dapr Job via the alpha1 Jobs API.
    POST http://localhost:3500/v1.0-alpha1/jobs/{job_name}
    Raises httpx.HTTPStatusError on Dapr API failure (caller handles as HTTP 503).
    """
```

**`parse_reminder_time` implementation notes**:
- Call `dateparser.parse(time_string, settings={"RETURN_AS_TIMEZONE_AWARE": True, "PREFER_DATES_FROM": "future", "TO_TIMEZONE": "UTC"})`
- If result is `None` → raise `ValueError("Could not parse time expression")`
- If result is in the past (< `datetime.now(UTC)`) → raise `ValueError("Scheduled time is in the past")`
- Return UTC-aware `datetime`

**`schedule_job` implementation notes**:
- Build payload: `{"dueTime": due_time.strftime("%Y-%m-%dT%H:%M:%SZ"), "data": data}`
- `DAPR_HTTP_PORT` from env (default `3500`)
- POST with `httpx` (sync, timeout=10s)
- Raise `httpx.HTTPStatusError` on non-2xx so the route handler returns HTTP 503

### 1.3 New File: `app/routes/jobs.py`

**Router prefix**: `/api` (registered in main.py, same as tasks router)

**Endpoints**:

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| POST | `/api/jobs/schedule` | JWT required | Accept NL reminder request; return job name + UTC fire time |
| POST | `/api/jobs/trigger` | localhost IP only | Alias for Dapr callback (spec compliance) |
| POST | `/job/{job_name}` | localhost IP only | Primary Dapr callback path |

**`POST /api/jobs/schedule` logic**:
1. Verify JWT → extract `user_id` (existing `get_current_user` dependency)
2. Verify `request.user_id == body.user_id` (cross-user spoofing guard)
3. DB query: fetch task by `(task_id, user_id)` — return 400 if not found
4. Call `parse_reminder_time(body.reminder_time_natural_language)` → 400 on `ValueError`
5. Build `job_name = f"reminder-{user_id}-{task_id}-{int(due_time.timestamp())}"`
6. Call `schedule_job(job_name, due_time, {"task_id": task_id, "user_id": user_id, "type": "reminder"})`
7. Return `ScheduleReminderResponse(job_name=..., due_time_utc=..., task_title=task.title)`

**`_handle_job_trigger(request, body)` shared handler**:
1. Check `request.client.host == "127.0.0.1"` → 403 if not
2. Extract `data = body.get("data", {})` — parse as `JobTriggerPayload`
3. DB query: fetch task by `(task_id, user_id)` — log WARNING + return `{"status": "ok"}` if not found
4. Call `publish_reminder_event(str(task.id), task.title, user_id)` (existing function)
5. Return `{"status": "ok"}`

**`POST /api/jobs/trigger`** → calls `_handle_job_trigger`
**`POST /job/{job_name}`** → calls `_handle_job_trigger` (ignores `job_name` path param)

### 1.6 MCP Tool: `app/mcp/server.py`

Add `schedule_reminder` as the 6th tool after `update_task`:

```python
@mcp.tool()
async def schedule_reminder(user_id: str, task_id: int, reminder_time_natural_language: str) -> str:
    """
    Schedule a future reminder for a specific task.
    Returns confirmation with job name and UTC fire time.
    """
```

**Logic**:
1. POST to `http://localhost:8000/api/jobs/schedule` (backend self-call via localhost)
   with body `{"user_id": user_id, "task_id": task_id, "reminder_time_natural_language": ...}`
   and `Authorization: Bearer <user_token>` header.
2. On success: return JSON string with `job_name`, `due_time_utc`, `task_title`
3. On 400/503: return error string for agent to surface as plain-language failure

**Note**: The MCP server runs as a subprocess of the backend. It can call
`http://localhost:8000` (the backend's own HTTP port) — this is a loopback call
within the same pod, not a cross-service HTTP call, so it complies with Principle XII
(no cross-service direct HTTP).
